## 2. ระบบของเรา

- **ระบบนี้ทำอะไร (2–3 ประโยค):** AHA เป็นเว็บแอปพลิเคชันสำหรับช่วยผู้สูงอายุจัดการตารางยา แจ้งเตือนการรับประทานยา และบันทึกสถานะการรับประทานยาที่ผู้ใช้ยืนยันด้วยตนเอง โดยเชื่อมโยงข้อมูลกับผู้ดูแลที่ได้รับอนุญาต ระบบมีฟังก์ชันสั่งงานด้วยเสียงแบบ Rule-based สำหรับช่วยใช้งานและตั้งเวลาแจ้งเตือน ซึ่งยังต้องทดสอบความแม่นยำในฉบับ Academic รวมถึงมีฟังก์ชันช่วยเหลือฉุกเฉิน (SOS) ตามขอบเขตการพัฒนาของโครงงาน
- **ผู้ใช้หลักและผู้มีส่วนได้ส่วนเสีย (ใครใช้ ใครได้รับผลกระทบ):** ผู้สูงอายุที่ใช้ระบบแจ้งเตือนการรับประทานยา และผู้ดูแลที่ติดตามข้อมูลการรับประทานยาและสถานะของผู้สูงอายุ
- **ผู้ใช้จริงที่จะชวนมาทำ UAT ได้ (หน่วยงานหรือกลุ่มผู้ใช้ ไม่ต้องใส่ชื่อบุคคล):** ผู้สูงอายุในครอบครัว ญาติผู้ใหญ่ และบุคคลใกล้ชิด เช่น พ่อแม่ ปู่ย่า ตายาย รวมถึงสมาชิกในครอบครัวที่ทำหน้าที่เป็นผู้ดูแล โดยเข้าร่วมทดสอบด้วยความสมัครใจ
- **การ deploy (ทดสอบที่ไหน ใช้งานจริงที่ไหน):** AHA มีเว็บไซต์ที่ให้บริการจริงแยกต่างหาก โดยใช้ Backend Services และ PostgreSQL สำหรับฉบับ Academic (AHA-T09) ใช้สภาพแวดล้อมแยกและข้อมูลจำลองเท่านั้น ไม่เชื่อมต่อระบบ Production; การยืนยันผลทดสอบของฉบับ Academic ยังไม่เสร็จ

## 3. เอกสารที่มีอยู่แล้ว

- **SRS ฉบับที่ / วันที่ / ตำแหน่งไฟล์ใน repo:** มีเอกสาร SE02 ส่วนที่ 3 เป็นฐานความต้องการ (`docs/srs/proposal.pdf`) และพบไฟล์ SRS-T09.pdf ในชุดเอกสารเดิม แต่ยังต้องตรวจฉบับและความครบถ้วนก่อนรับรอง SRS 1.0
- **จำนวนความต้องการ:** เชิงฟังก์ชัน **11 ข้อ** (FR-01 ถึง FR-11) · เชิงไม่เป็นฟังก์ชัน **7 ข้อ** (NFR-01 ถึง NFR-07) ตามเอกสาร SE02
- **RTM อยู่ที่:** ยังไม่มีเอกสาร Requirements Traceability Matrix (RTM) ฉบับทางการแยกต่างหาก
- **แบบสถาปัตยกรรม / ER / API spec อยู่ที่:** มีแผนภาพสถาปัตยกรรมเบื้องต้นในเอกสาร SE02 ส่วนที่ 5.1 รูปที่ 4 และรายละเอียดเทคโนโลยีในส่วนที่ 5.2 ส่วนเอกสาร ER Diagram และ API Specification ฉบับทางการยังไม่ได้ยืนยันตำแหน่งไฟล์

## 4. สถานะตอนนี้

- **Sprint ปัจจุบันและสิ่งที่กำลังทำ:** ปัจจุบันอยู่ในระยะทดสอบและปรับปรุงระบบ (Testing & Improvement Phase) โดยยังไม่ได้กำหนดหมายเลข Sprint อย่างเป็นทางการ กำลังตรวจสอบความถูกต้องของระบบแจ้งเตือน ตรวจสอบการตีความคำสั่งเสียงแบบ Rule-based ให้สามารถตั้งเวลาได้แม่นยำ รวมถึงทดสอบการกู้คืนข้อมูลจำลองเพื่อรองรับกรณีระบบเสียหาย
- **ส่วนที่ทำเสร็จแล้ว:** มีระบบบัญชีผู้ใช้งานและการเข้าสู่ระบบ ระบบจัดการรายการยาและตารางแจ้งเตือน หน้าจอสำหรับผู้สูงอายุและผู้ดูแล ระบบเชื่อมโยงผู้สูงอายุกับผู้ดูแล และระบบบันทึกข้อมูลบนฐานข้อมูล PostgreSQL โดยระบบเปิดให้ทดลองใช้งานผ่านเว็บไซต์จริงแล้ว ส่วนความสมบูรณ์ของการแจ้งเตือนข้ามอุปกรณ์ ระบบเสียง AI และ SOS ยังคงต้องตรวจสอบตามกรณีทดสอบที่กำหนด
- **การทดสอบที่มีอยู่แล้ว (ถ้ายังไม่มี เขียนว่ายังไม่มี):** เคยทดลองตั้งเวลาแจ้งเตือนการรับประทานยาและตรวจสอบการทำงานเบื้องต้นแล้ว แต่ยังไม่ได้รวบรวมผลการทดสอบอย่างเป็นระบบ โดยจะรวบรวมหลักฐานเดิมที่ผ่านการคัดกรองและทดสอบในสภาพแวดล้อมแยกก่อนสรุปผลความถูกต้อง อัตราความสำเร็จ และความตรงเวลาของการแจ้งเตือน

## 5. ส่วนที่ทีมคิดว่าเสี่ยงที่สุด 3 อย่าง

ใช้ในการวางแผนการทดสอบตามความเสี่ยงครั้งที่ 5 (CP2)

| ส่วนของระบบ | ทำไมคิดว่าเสี่ยง | ถ้าพังจะกระทบใคร อย่างไร |
|---|---|---|
| **1. ระบบคำสั่งเสียงแบบ Rule-based และการตีความคำสั่ง** | ระบบอาจแปลงเสียงเป็นข้อความหรือตีความเวลาจากคำสั่งผู้ใช้ไม่ถูกต้อง เช่น ผู้ใช้สั่งให้แจ้งเตือนเวลา 11:00 น. แต่ระบบบันทึกเป็น 11:01 น. ซึ่งอาจเกิดจากความคลาดเคลื่อนในกระบวนการรู้จำเสียงหรือประมวลผลคำสั่ง | กระทบผู้สูงอายุที่ต้องการตั้งเวลาแจ้งเตือนให้ถูกต้อง อาจทำให้ได้รับการแจ้งเตือนไม่ตรงเวลา และลดความเชื่อมั่นต่อความถูกต้องของระบบ |
| **2. ระบบแจ้งเตือนการรับประทานยา** | การแจ้งเตือนอาจล่าช้าหรือไม่ทำงานเมื่อปิดหน้าเว็บ ล็อกหน้าจอโทรศัพท์ ไม่ได้รับอนุญาตให้ส่ง Notification หรืออุปกรณ์และระบบปฏิบัติการมีข้อจำกัดแตกต่างกัน | ผู้สูงอายุอาจไม่ได้รับการแจ้งเตือนตามกำหนด และผู้ดูแลอาจไม่สามารถติดตามสถานะการรับประทานยาได้อย่างถูกต้องและทันเวลา |
| **3. ระบบความปลอดภัยและการกู้คืนข้อมูล** | ระบบจัดเก็บข้อมูลบัญชีและข้อมูลการใช้ยาซึ่งต้องป้องกันการเข้าถึงโดยไม่ได้รับอนุญาต รวมถึงมีความเสี่ยงจากการโจมตีเรียกค่าไถ่ การลบข้อมูล หรือความเสียหายของฐานข้อมูล หากระบบสำรองข้อมูลและกู้คืนไม่มีประสิทธิภาพ | กระทบผู้สูงอายุและผู้ดูแล เนื่องจากอาจเกิดการรั่วไหลหรือสูญหายของข้อมูลส่วนบุคคลและตารางยา ทำให้ไม่สามารถใช้งานระบบได้ตามปกติ และลดความน่าเชื่อถือของระบบ |
