# V&V Strategy ของทีม

- รหัสทีม: T09
- ระบบ: AHA — ระบบผู้ช่วยแจ้งเตือนการรับประทานยาและติดตามความร่วมมือในการใช้ยาสำหรับผู้สูงอายุโดยเชื่อมโยงกับผู้ดูแล
- ฉบับ / วันที่: 1.0 / 27 พ.ย. 2569

## 1. ระดับความสำคัญของระบบ (integrity level ตาม IEEE 1012)

| คำถาม | คำตอบของทีม |
|---|---|
| ผลเสียร้ายแรงที่สุดและผู้ได้รับผลกระทบ | แจ้งเตือนยาผิดเวลา/ไม่แจ้งเตือน หรือ SOS ไม่ถึงผู้ดูแล อาจทำให้ผู้สูงอายุพลาดยา/ความช่วยเหลือและเกิดอันตรายรุนแรงถึงชีวิตทางอ้อม; ข้อมูลการใช้ยาอาจรั่วไหล |
| ความรุนแรง | ร้ายแรงมาก (กรณีผู้สูงอายุที่มีความเสี่ยงสูง) |
| โอกาสเกิด | บางครั้ง (ประเมินเบื้องต้น ยังไม่มีสถิติยืนยัน) |
| Integrity level ทั้งระบบและเหตุผล | ระดับ 3 ตามช่อง 4 หรือ 3: ระบบสนับสนุนการดูแล ไม่ควบคุมการให้ยาหรือการรักษาโดยตรง แต่ความผิดพลาดอาจกระทบสุขภาพและข้อมูลส่วนบุคคล |
| ส่วนที่ระดับสูงกว่าและเหตุผล | ระดับ 4: การแจ้งเตือนยา (รวมการตีความเวลาเสียงก่อนบันทึก) และ SOS เพราะความผิดพลาดในงานที่ไวต่อเวลาอาจก่ออันตรายรุนแรง; แจ้งอาจารย์เพื่อตกลงการทวนสอบเพิ่ม |

## 2. ทดสอบอะไร ระดับไหน เมื่อไร

| ระดับการทดสอบ | ทดสอบอะไรในระบบของเรา | Sprint หรือช่วงเวลา | เครื่องมือ | ผู้รับผิดชอบ |
|---|---|---|---|---|
| component (unit) | การตีความเวลาเสียง การคำนวณตารางยา และการตรวจข้อมูล | ก่อน CP2 และทุกครั้งที่แก้โค้ด | Node.js Test Runner, Jest | พชร |
| integration | Auth, Reminder, Notification, PostgreSQL: สิทธิ์ผู้ดูแล การส่งแจ้งเตือน และกู้คืนข้อมูลจำลอง | CP2–CP4 | Jest, Supertest, PostgreSQL ทดสอบ | พชร; ชัยมนัสร่วมตรวจ |
| system | เส้นทางตั้งยา–เตือน–ยืนยัน–ติดตาม, SOS, ปิดหน้าเว็บ/ล็อกจอ และข้อจำกัดอุปกรณ์ | CP3–CP5 | Chrome DevTools, เบราว์เซอร์และมือถือจริง, Checklist | ทั้งสองคน |
| acceptance (UAT) | ภารกิจผู้สูงอายุและผู้ดูแลตาม Acceptance Criteria ด้วยข้อมูลจำลอง | ก่อน CP5 | UAT Checklist, บันทึกผล | ชัยมนัส; พชรร่วมทดสอบ |

## 3. ทวนสอบเชิงสถิต (ไม่ต้องรันโค้ด)

| สิ่งที่ทบทวน | วิธี | เมื่อไร |
|---|---|---|
| SRS | inspection ไขว้ทีม ด้วยรายการตรวจ SRS | ครั้งที่ 3 (CP1) |
| เอกสารออกแบบ | peer review แผนภาพสถาปัตยกรรม/ข้อมูล/API เทียบ SRS และ RTM | ครั้งที่ 4 ก่อน CP2 |
| โค้ด | Pull Request review, ESLint, ตรวจสิทธิ์/ข้อมูลลับ; ให้สมาชิกทั้งสองร่วมตรวจส่วนระดับ 3 ขึ้นไปและหาผู้ทบทวนเพิ่มเติมเมื่อจำเป็น | ก่อน merge ทุกครั้ง |

## 4. ชนิดการทดสอบ

- เชิงฟังก์ชัน: FR-01–FR-11 ตาม SE02/SRS; เน้น FR-03 (แจ้งเตือน), FR-07 (สิทธิ์), FR-08 (เสียง), FR-09 (SOS)
- เชิงไม่เป็นฟังก์ชัน: Reliability (ความตรงเวลา ความพร้อมใช้งานและการกู้คืน) และ Security (การเข้าถึงตามสิทธิ์และการปกป้องข้อมูลส่วนบุคคล) ตาม ISO/IEC 25010
- Regression: ทดสอบซ้ำการตั้งยา แจ้งเตือน เสียง สิทธิ์ และ SOS ทุกครั้งที่แก้ส่วนเกี่ยวข้อง/ก่อน release; เป้าหมาย branch coverage ส่วนระดับ 3 ขึ้นไป ≥ 90% เทียบส่วนทั่วไป ≥ 80% และตรวจสิทธิ์ทุกบทบาท
- สิ่งที่ตั้งใจไม่ทดสอบ: ประสิทธิผลทางคลินิก การวินิจฉัย/สั่งยา และการตอบสนองของหน่วยฉุกเฉินจริง เพราะอยู่นอกขอบเขต; ไม่ทดสอบโจมตี Production หรือใช้ข้อมูลผู้ใช้จริง

## 5. ส่วนที่เสี่ยงจาก V&V Profile

| ส่วนที่เสี่ยง | ระดับหรือวิธีที่จะจับข้อบกพร่องได้เร็วที่สุด |
|---|---|
| คำสั่งเสียงแบบ Rule-based และการตีความคำสั่ง | Unit: ค่าขอบเขตเวลา คำสั่งกำกวม และการยืนยันก่อนบันทึก |
| ระบบแจ้งเตือนการรับประทานยา | Unit: scheduler/เวลา; Integration: การส่งต่อเหตุเตือนและกรณีล้มเหลว; System: ล็อกจอ/ปิดเว็บ |
| ความปลอดภัยและการกู้คืนข้อมูล | Static review สิทธิ์/ข้อมูลลับ; Integration: ข้ามบัญชี/เพิกถอนสิทธิ์ และ restore ข้อมูลจำลอง |
